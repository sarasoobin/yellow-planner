## 1. 이 앱이 푸는 문제

기존 캘린더는 **"중간고사"와 "목데이터 연결하기"를 같은 칸에 같은 크기로** 적습니다.
중요한 일정이 자잘한 할 일 사이에 묻힙니다.

그래서 **적는 곳을 아예 분리**했습니다.

| | 어디에 | 무엇을 |
|---|---|---|
| 중요한 일정 | 월간 페이지의 달력 칸 | 시험, 마감, 약속 |
| 자잘한 할 일 | 주간 페이지의 요일 칸 | 강의 듣기, 장보기 |

주간 페이지 각 칸 맨 위에는 그 날 달력에 적은 일정이 색 띠로 따라옵니다.
"오늘 뭐 하지"를 볼 때 "이번 주에 뭐가 걸려 있지"가 같이 보이게 하려는 것입니다.

## 2. 크게 판단한 것 다섯 가지

### 2-1. 인가를 앱이 아니라 DB에 뒀다

앱 코드에서 `user_id` 로 거르지 않습니다. PostgreSQL의 RLS가 DB 레벨에서 강제합니다.

```sql
create policy "본인 항목만" on public.items for all
  using ((select auth.uid()) = user_id)
  with check ((select auth.uid()) = user_id);
```

앱에 버그가 있어도 남의 데이터는 안 새어나갑니다. 남의 id로 삭제를 시도하면
에러가 아니라 **0건 처리**로 끝납니다.

계정 A/B로 교차 검증했습니다 — 화면에서 숨긴 것이 아니라 서버 응답에 애초에
안 들어 있습니다.

### 2-2. 테이블 하나로 네 화면을 굴린다

표지 · 월간 왼쪽 칸 · 달력 칸 · 주간 요일 칸은 전부 **"날짜에 묶인 짧은 글 + 체크"**
라는 같은 구조입니다. 테이블을 나누는 대신 `kind` 컬럼 하나로 구분했습니다.

덕분에 편집기 한 벌(`PaperBlock`)과 Server Action 하나(`saveBlock`)가 네 화면
전부를 담당합니다. 새 화면이 생겨도 `kind` 만 늘리면 됩니다.

### 2-3. 줄 목록이 아니라 종이 한 면으로

처음에는 "할 일 하나 = DB 한 행" 이었습니다. 그런데 종이 다이어리는 그렇게 안
씁니다. 마구잡이로 쓰고, Enter로 줄을 바꾸고, 필요한 줄에만 네모를 그립니다.

그래서 **한 칸이 통째로 한 행**이 됐습니다. 체크박스도 컬럼이 아니라 글자(`☐`/`☑`)로
글 안에 들어갑니다 — 줄 앞이든 문장 중간이든 아무 자리에나 그릴 수 있습니다.

대가: 글을 HTML로 저장해야 했고, 그래서 저장 직전에 `sanitize-html` 로 허용 목록에
없는 태그와 style을 전부 걸러냅니다.

### 2-4. "적는다"는 감각을 위해 직접 만든 것

리치 텍스트 라이브러리를 넣지 않았습니다. 종이 느낌을 내려면 결국 다 뜯어고쳐야
하는데, 그럴 바엔 `contenteditable` 위에 필요한 것만 얹는 편이 빨랐습니다.

- `/` 를 치면 뜨는 메뉴 (노션 방식). 글을 적다 말고 위로 올라가지 않아도 됨
- 글자를 고르면 그 자리에 뜨는 막대
- 줄 맨 앞 `# ` `## ` `### ` 를 글자 크기로

### 2-5. 화면에 그리는 것과 저장하는 것을 나눴다

체크 표시 · 취소선 · 밑줄은 **글에 저장하지 않습니다.** 사실만 저장하고
(`☑` 이라는 글자, `text-decoration: underline`) 보이는 줄은 자리를 재서 그립니다.

왜냐하면 체크는 글 안의 한 글자라 **그 글자만 빨갛게 하거나 키울 수가 없기**
때문입니다. CSS로는 글자 하나를 집을 수 없습니다. 그래서 글자는 그대로 두고
그 위에 색연필 획을 그립니다. 네모를 넘어가도 둡니다 — 종이에 그으면 원래 그렇습니다.

## 3. 오래 걸린 문제와 어떻게 잡았나

### 3-1. 적던 글이 자꾸 처음 내용으로 되돌아갔다

`/` 를 칠 때마다 방금 친 글자가 사라지고 커서가 튀었습니다. **세 번을 추측으로
고쳤는데 다 빗나갔습니다.** Playwright로 실제 크롬을 계측하고 나서야 잡혔습니다.

React 19는 prop이 바뀌었는지 값이 아니라 **참조**로 판단합니다.
`dangerouslySetInnerHTML={{ __html: 문자열 }}` 은 매 렌더마다 새 객체를 만들기
때문에, 내용이 같아도 매번 `innerHTML` 을 다시 써넣고 있었습니다.

계측 증거: 편집기 노드는 그대로인데 자식 11개가 통째로 교체(added 11 / removed 11).

**배운 것 — 추측으로 세 번 고치느니 한 번 재는 게 빠르다.**

### 3-2. "4줄 이상 쓰면 저장이 안 된다"

재현하는 데 제일 오래 걸렸습니다. 실제 크롬으로 3·4·5·8줄, 자동 줄넘김, 폰 크기,
적고 바로 링크 클릭까지 다 해봤지만 전부 저장됐습니다.

원인은 코드가 아니라 **DB에 옛 200자 제약이 남아 있던 것**이었습니다.
`supabase/latest.sql` 에서 5000자로 늘렸는데 그 파일을 다시 실행하지 않았습니다.
제 시험 글자가 짧아서("하나/둘/셋/넷") 200자를 안 넘겼던 것입니다.

150자 저장됨 / 190자 저장됨 / 210자 거절 — 길이로 재고 나서 확정했습니다.

**배운 것 — 앱과 DB는 따로 배포된다. 코드를 아무리 올려도 DB 설정은 안 바뀐다.**

### 3-3. "달력에 썼는데 주간 갔다 오면 사라진다"

처음에 "배포판에서 3/3 재현했다"고 보고했는데 **틀렸습니다.** 제 시험 스크립트가
다른 달의 칸을 읽고 있었습니다.

제대로 다시 재보니 저장은 정상이었고, 진짜 문제는 따로 있었습니다.
"달력으로" 가 **그 주 월요일이 속한 달**로 갔습니다. 2026년 7월은 1일이 수요일이라
첫 주 월요일이 6월 29일입니다. 7월 1~5일에 적고 주간에 갔다 돌아오면 **6월 달력**이
열리고, 6월의 그 자리는 당연히 비어 있습니다.

**배운 것 — 재현했다고 말하기 전에 내가 무엇을 보고 있는지부터 확인한다.**

### 3-4. 스티커가 버벅거린다

헤드리스 브라우저로는 프레임 간격도 스크립트 시간도 차이가 안 나와서 못 쟀습니다.
그래서 "비싼 것이 확실한 일"을 걷어내는 쪽으로 갔습니다.

1. 크기를 바꿀 때 매 프레임 SVG를 다시 그림 (별의 `feTurbulence` 가 비쌈)
   → 끄는 동안엔 그림 크기를 붙들고 `transform` 으로만 늘림
2. 손을 움직일 때마다 층 전체가 다시 그려짐 → 스티커 하나짜리 컴포넌트로 분리
3. 옮길 때 `left/top` 을 바꿔 자리를 다시 계산 → `transform` 으로만 밀기

그리고 진짜 원인이 하나 더 있었습니다. **놓는 순간 원래 자리로 되돌아갔다가
저장되면 다시 갔습니다.** 제 컴퓨터는 왕복이 50ms 라 안 보였고, 배포된 서버에서
재보니 확실히 보였습니다. 놓은 자리를 화면이 먼저 붙들게 고쳤습니다.

**배운 것 — 로컬에서 안 보이는 문제가 있다. 느린 왕복을 흉내내서 재야 한다.**

## 4. 어떻게 검증했나

테스트 프레임워크를 안 넣었습니다(3일 계획의 판단). 대신 **Playwright로 실제
크롬을 띄워** 확인했습니다. 화면에서 실제로 벌어지는 일만 증거로 인정했습니다.

- 빈 화면·로딩·에러 16/16
- 형광펜·밑줄·취소선 16/16
- 마크다운 제목 6/6, 체크 표시 6/6
- 폰 월간 12/12, 스티커 6/6, 옮기기 5/5, 가장자리 4/4

시험은 데모 계정의 **2029~2030년 날짜**에서 했습니다. 실제로 쓰는 달을 안 건드리려는
것이고, 끝나면 지웠습니다.

## 5. 알면서 안 한 것

`README.md` 의 "다음 단계"와 같습니다.

- **테스트 코드** — 지금은 손으로 Playwright를 돌립니다. `lib/dates.ts` 의 주/월
  경계 계산부터 단위 테스트로 묶는 것이 우선입니다
- **동시 편집 충돌** — 두 기기에서 같은 칸을 열어두면 나중에 저장한 쪽이 앞의 것을
  조용히 덮어씁니다. `updated_at` 비교가 필요합니다
- **오프라인** — 인터넷이 끊기면 저장이 실패합니다. 다이어리는 지하철에서 펴는
  물건이라 이게 제일 아쉽습니다
- **되돌리기** — 형광펜을 잘못 칠하면 같은 자리를 다시 긁어 지우는 것이 유일한 방법입니다

## 6. 손대기 전에 알아야 할 것

새로 이 코드를 만지는 사람이 모르면 반드시 한 번 데는 것들입니다.

1. **`AGENTS.md` 를 먼저 읽으세요.** 이 Next.js(16.2)는 예전과 다릅니다.
   `middleware.ts` 대신 `proxy.ts`, `cookies()`·`params`·`searchParams` 는 전부 async,
   에러 화면은 `reset` 이 아니라 `unstable_retry`. 규약은
   `node_modules/next/dist/docs/` 에서 확인하세요.

2. **`PaperBlock` 은 한 번 열리면 서버 내용을 다시 안 받아옵니다.**
   적던 글이 되돌아가는 문제를 막으려고 일부러 그렇게 했습니다(§3-1).
   그래서 다른 날을 보여줄 때는 `key` 로 새로 만들어야 합니다.

3. **색은 `globals.css` 의 `@theme` 한 곳에서만 고칩니다.**
   토큰을 못 쓰는 곳이 네 군데 있고 전부 이유를 주석으로 적어뒀습니다 —
   `toolbar.tsx`(펜 색), `stickers.ts`(형광펜), `manifest.ts`·`layout.tsx`(themeColor),
   `global-error.tsx`(globals.css 가 안 실림).

4. **DB를 고쳤으면 `supabase/latest.sql` 을 Supabase에서 실행하세요.**
   배포만으로는 안 바뀝니다(§3-2). 여러 번 실행해도 안전하게 돼 있습니다.

5. **`npm run icons`** — 아이콘은 `src/app/icon.svg` 한 장에서 전부 만들어냅니다.
